# QA update - 2 November 2026

This pass follows the manual-QA request. It combines targeted source review, reproduced failures and automated browser/API regression. Test writes use disposable databases, not the running showcase. It does not certify every internal path or external service.

## Found and corrected

| Finding | Correction | Evidence |
| --- | --- | --- |
| An assignment starting after the lease end was accepted when its own end was blank; the default end then preceded its start. | Server checks assignment start against lease end before applying defaults; invalid writes preserve the original record. | New service regression. |
| Login checked trimmed email but counted failed attempts using untrimmed email. | Login throttling now uses the same trimmed, lowercase identity, so extra spaces do not reset the limit. | Eight padded failures followed by a valid-password attempt still return 429 in an isolated fixture. |
| Array-valued profile email caused a TypeError; object names were coerced to text and long names silently truncated. | Profile name/email types are validated; names must contain 2–150 trimmed characters. Invalid input returns 422 and preserves identity. | New service regression. |
| Array-valued portal message fields caused a server error. | Message subject/body must be nonblank strings before length/trim handling. Invalid requests return 422 with no message created. | Extended HTTP API regression. |
| Password dialogs stated the length rule but did not enforce it before submission. | Shared new-password controls require 12–200 characters. Existing server enforcement remains. | Browser check verifies short input produces an inline error and never calls Save. |
| Tenant profile name/email lacked required browser checks. | Required fields and name length constraints are checked before profile dispatch. | Browser check verifies a blank name does not change the stored identity. |
| Admin's Tenant role did not require its permanent Tenant ID in the browser. | Tenant ID becomes required/enabled only for Tenant role and disabled for other roles. | Browser role-switching/validity check; existing server linking/permission checks remain. |

The four backend reproductions failed before repair (`data/qa-validation-before.log`) and pass afterward (`data/qa-validation-fixed.log`). Focused backend plus form-browser run: **40 passed**, no failures (`data/qa-audit-targeted.log`).
